There is a statistic called the z-score, which is used to describe how much it deviates from the mean. The equation goes like this (value - mean)/sd.

This works well for a normal distribution and the z-score can be used to identify outliers, usually a rule of thumb is 4. 

However, when there is a quite some outliers, the distribution is not normal anymore, especially the sd can be inflated a lot by them. In this case, the z-score might look normal (<4) for some of the outliers. 

To deal with this problem, the idea of median absolute deviation (MAD) is introduced. This is how it works:

1. get the median from the samples
2. minus median from everyone and take the absolute value, this is basically their distances from the median
3. get the median of step 2, and it is MAD

Why this is going to help? First of all, instead of minus the mean, it minus the median. Secondly, instead of using mean in step 3, it uses the median. Then we got something called the "robust z-score".

Look at the three forms of z-score below:

1. the concept of z-score: (value - center) / spread
2. normal z-score: (value - mean) / sd
3. robust z-score: (value - median) / mad 

We already know that when the distribution is normal, median = mean. How about mad? __Would mad = sd if the distribution is normal?__

The answer is no! Oh my. Damn stats. OK let's work out the relationship between mad and sd under a normal distribution.

Remember there was this magic number, 1.96, in normal distribution? sd * 1.96 would cover 95% of a normal distribution (two-tailed). Today we are going to introduce another magic number: 1.4826

If we check the function `mad` in R, it looks like this:

```
mad
function (x, center = median(x), constant = 1.4826, na.rm = FALSE, 
    low = FALSE, high = FALSE) 
{
    if (na.rm) 
        x <- x[!is.na(x)]
    n <- length(x)
    constant * if ((low || high) && n%%2 == 0) {
        if (low && high) 
            stop("'low' and 'high' cannot be both TRUE")
        n2 <- n%/%2 + as.integer(high)
        sort(abs(x - center), partial = n2)[n2]
    }
    else median(abs(x - center))
}
```

This low/high part is telling the program what to do if the number of values are even. Mean by defaul, or you can ask it to use the lower or the higher one if you prefer to use one of the values. So this whole function can be boil down to:

`1.4826 * median(abs(x - median(x)))`

So now, why 1.4826?

In order to use the MAD as a consistent estimator for the estimation of the standard deviation σ, a constant scale factor needs to be introduced, and its value depends on the distribution. So now we just need to calculate the MAD under a standardized normal distribution (mean = 0 and sd = 1), then we would know what the scale factor should be for it to be scale back to 1.

The __derivation__ process is demonstrated on the [wiki page](https://en.wikipedia.org/wiki/Median_absolute_deviation). It is pretty straight forward once you understand that why P(|X - μ| =< MAD) = 0.5. This is because:

1. in normal distribution, μ = median
2. after step 2, where every value gets its distance from the median, MAD is the median distance. This means half of the values are even more dispersed (higher than MAD), and half of the values are tighter (lower than MAD), thus the 0.5.

Once we understrand the 0.5, it is easy to know that under a normal distribution, it is the area under the curve between 25% to the 75% percentile in the CDF (cumulative distribution function).
